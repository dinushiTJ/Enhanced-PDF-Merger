Privacy and Security

How your files are handled by PDF Merger.

Local processing

Your PDFs are processed in your browser

PDF Merger does not provide an application upload endpoint. Files selected in the tool are read and processed locally by your browser, then the merged result is created as a temporary browser download.

Because this is client-side software, browser extensions, malware, or compromised third-party JavaScript running in the page could access files that you select. The application pins its CDN scripts with Subresource Integrity, but sensitive documents should only be processed in a trusted browser environment.

Safety limits

Browser and processing limits

The tool limits each input file to 100 MB, the combined input size to 250 MB, each source PDF to 500 pages, and the inline preview to 100 pages. These limits reduce the risk of excessive browser memory and CPU use, but unusually complex PDFs can still affect browser performance.

PDF passwords are used in page memory while an unlock or merge operation needs them. The tool does not send them to an application server.

PDF content

Downloaded PDFs are not fully sanitized

The merger copies pages from your source PDFs. Existing annotations, links, attachments, or other PDF actions may remain in the downloaded file. Open downloaded PDFs with a trusted, up-to-date PDF viewer and do not treat the merger as a malware scanner or document sanitizer.

PDF Merger preserves normal PDF content and quality instead of rasterizing every page, so some source-document features are intentionally retained.

Deployment

Static hosting security

This project is hosted as a static GitHub Pages site. The pages include a Content Security Policy and referrer policy in their HTML, but GitHub Pages does not provide this project with custom HTTP response headers such as HSTS, X-Frame-Options, or X-Content-Type-Options.

For stronger production guarantees, deploy the same static files behind a host or reverse proxy that supports security response headers.
