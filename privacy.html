Security overview

Privacy, by design.

Your documents are processed in your browser, not uploaded to an application server.

Client-side processingHTTPS deliveredNo analytics
01 / Processing

Local by default

Files are read, merged, previewed, and downloaded inside your browser. There is no application upload endpoint.

02 / Integrity

Dependencies pinned

CDN scripts use pinned versions and Subresource Integrity checks. The PDF.js worker is served locally.

03 / Resilience

Abuse limits

Input size, page count, preview, and concurrent processing limits reduce browser resource exhaustion.

Important boundary Client-side processing protects against routine server uploads, but it cannot protect files from a compromised browser, extension, device, or trusted script.
A

Data handling

What happens to your files

PDF Merger processes selected files locally and creates the merged result as a temporary browser download. The project does not operate a file-upload API, database, or document storage service.

PDF passwords are used in page memory only while an unlock or merge operation needs them. Do not use the tool on a device or browser you do not trust.

C

PDF boundaries

The output is not a malware scanner

The merger copies pages rather than rasterizing them. Existing annotations, links, attachments, or other PDF actions may remain in the downloaded file.

Open downloaded PDFs with a trusted, up-to-date viewer. Do not treat PDF Merger as a document sanitizer or security scanner.

D

Deployment

How the site is protected

The site is hosted on GitHub Pages and delivered over HTTPS with HSTS. Pages include a Content Security Policy and a restrictive referrer policy.

GitHub Pages does not let this project configure additional response headers such as X-Frame-Options or X-Content-Type-Options. A reverse proxy or security-focused host would be required for those controls.
